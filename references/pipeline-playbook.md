# 出图管线改造 Playbook：步数当可调成本项

## 第 1 步：建对照表（步数 vs 延迟 vs 质量）

真实数据，不是感觉。模板：

```markdown
# 出图步数对照表
场景: <产品名/用途>
| 步数 | 延迟(P50/P99) | 质量分(GenEval/PickScore/人评) | 成本/张 | 可用场景 |
|---|---|---|---|---|
| 1 |  |  |  | 草稿/预览/A-B选样 |
| 4 |  |  |  | 终稿 |
| 8 |  |  |  | 仅当 4 步质量不达标 |
结论: <哪些场景砍到 1 步，哪些保留多步>
```

**决策规则**：
- 实时预览、批量出草稿、A/B 选样 → 一步
- 终稿精修 → 多步（且仅当对照表证明多步质量增量 > 延迟/成本增量）
- 对照表证明 1 步与 4 步质量分差 < 阈值 → 全线一步，多步是历史包袱

## 第 2 步：后训练改造队列（别从头训）

论文最关键可复用点：**已训练好的多步模型，后训练微调即可改造成一步生成器**，不需要重训底座。

落地动作：

```markdown
# 四步→一步改造队列
| 模型 | 用途 | 后训练接口 | 数据量需求 | 改造成本 | 优先级 | 备注 |
|---|---|---|---|---|---|---|
| FLUX.2 4B | 主图 | ✓ |  |  | P0 | 论文已验证路线 |
| ... | ... |  |  |  |  |  |
```

- 只列**支持后训练接口**的模型进入队列
- 后训练接口不可用的 → 才考虑重训，且须写明理由（validate.py 会拦"有后训练接口却标了重训"）
- 改造验证：改造后模型跑对照表，质量分达标才替换线上

## 第 3 步：三个能上生产的新场景

一步生成的价值不在"更快一点"，而在**打开原本不可能的场景**：

| 场景 | 原来为什么不行 | 现在怎么做 |
|---|---|---|
| 低延迟交互 | 多步延迟 > 交互容忍（边说边出图需要秒级） | 一步 + 流式，对话即出图 |
| 端侧部署 | 多步推理端侧跑不动 | 一步 + 小模型（4B 级），手机/浏览器本地 |
| 大批量快速渲染 | 多步 × 万张 = 成本爆炸 | 一步 × 万张，电商主图/素材海选 |

**选型纪律**：按这三条挑业务里最先受益的口子，别一上来追求画质超越原模型——画质超越是后训练的自然结果，不是立项理由。

## 第 4 步：模式覆盖度探针（防分数失明）

常规指标（FID、PickScore）是聚合值，看不出"某一类悄悄消失"。给评测集加一条**类别配额覆盖率**：

```markdown
# 类别配额覆盖率
评测集真实分布: 猫 5% / 狗 8% / 飞机 3% / ...
生成 N=500 张的类别占比: 猫 1.2% / 狗 7.9% / 飞机 3.1% / ...
覆盖率: |生成占比 - 真实占比| ≤ 配额容差(±2pp) 的类别数 / 总类别数
报警: 覆盖率 < 90% 或任一类别占比 < 真实占比 × 0.5
```

- 这是发现"分数失明"的**廉价探针**：每次跑评测顺手统计
- 报警后的处置：查 LP 约束/配额锁定是否生效，而不是加步数（步数解决不了类别消失）
- 迁移到其他域：任何"按分布生成/采样"的系统（推荐流、素材库、合成数据）都该有这条探针

## 工程纪律：固定归一化

- 归一化/权重系数禁止跟着当前生成质量动态变化（自我开脱）
- 参照物必须是外部固定参照（真实训练集与验证集的固定差值）
- 自查问题：**"我的指标里，有没有哪项的分母/权重是模型自己当前输出决定的？"** 有 → 改成固定参照

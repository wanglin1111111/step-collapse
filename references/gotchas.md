# 坑位清单

## 分数失明（最隐蔽）

**坑**：某类物体/某类请求生成占比悄悄降到真实分布的一半以下，但 FID/PickScore 等聚合指标正常，训练循环也看不到明显梯度异常。
**问题**：聚合值把"一类消失"摊平进了正常值里；占比低 → 梯度信号微弱 → 系统自发不纠偏。
**对策**：类别配额覆盖率探针（每次评测顺手统计）；报警后查约束，不是加步数。

## 自我开脱式归一化

**坑**：归一化系数/难度权重跟着当前生成质量动态变化——生成越烂，难维度权重被自动压低，指标反而好看。
**问题**：参照物是模型自己的当前输出 = 模型给自己打分；缺陷被掩盖而不是暴露。
**对策**：参照物必须是外部固定参照（真实训练/验证集的固定差值）；自查"我的指标分母/权重是谁定的"。

## 堆组件治标

**坑**：模式坍塌了 → 加组件数量/加参数容量 → 暂时缓解 → 复发。
**问题**：表达力不是病根；样本与组件之间缺硬性约束，加多少组件都会自发漂向坍塌。
**对策**：表达力（粒度）+ 约束（配额/配对）缺一不可；只有前者 = 复发只是时间问题。

## 从头训的诱惑

**坑**：看到"一步生成"就想去训一个新模型，从头走一遍训练周期。
**问题**：论文最关键可复用点是**后训练改造**——已有多步模型微调即可一步化，不重训底座。
**对策**：改造队列先列后训练接口；接口不可用才重训且须写明理由。

## 追求画质超越当立项理由

**坑**：立项目标是"一步模型画质要超过原四步模型"，做不到就不上。
**问题**：一步生成的价值在打开原本不可能的场景（低延迟/端侧/大批量），画质超越是后训练的自然结果，不是前提。
**对策**：按三个场景口子立项；对照表证明质量分在可接受带内即可。

## unify 失败硬套

**坑**：两派方案其实不同构，硬写成一个模板，统一后两派能力都打折。
**问题**：unify 的前提是"能写成同一模板的不同参数选择"；不同构时强行 unify = 双重损失。
**对策**：先找共同模板；找不到 → 场景分流（哪类请求走 A 派、哪类走 B 派），别硬套三步。

## 造"折中版"了事

**坑**：unify 之后造了一个写死的折中配置，不调参数，不跑多档位对照。
**问题**：粒度价值在"可调"；写死折中 = 没造中间档位，只是换了个中点。
**对策**：粒度参数可设（K=1/4/16 并行跑对照），让数据选档位。

## 约束加错位置

**坑**：粒度没调通就先上配额约束，锁死了错误的分配。
**问题**：约束是"锁死分配"，前提是当前分配是对的；粒度错误时锁定 = 把错固化。
**对策**：顺序纪律——unify → 粒度调通（对照数据说话）→ 才上约束。

## 砍步不诊断

**坑**：不管每个迭代步骤在补什么缺陷，一律砍到一步。
**问题**：补不同缺陷的步骤（一步补画质、一步补合规检查）不可合并；一刀切砍 = 砍掉合规。
**对策**：先逐条标注"在补哪个缺陷"，同缺陷重复还债的才合并。

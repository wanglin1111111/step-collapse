# 通用三步：unify → 中间粒度 → 硬性约束

MGFlow 的外壳是生图，内核是任何"两派方案各走极端"问题的通用解法。

## 适用判据（三个全中才用）

1. **存在两派方案**，各自解决一半问题，且各自走向极端（A 派丢 B 能力，B 派丢 A 能力）
2. **两派其实同构**——能写成同一个模板的不同参数/选择（MGFlow 实证：FD-Loss 与 Drifting = 同一"分布模型+差异度量"框架）
3. **系统有自发坍塌倾向**——不加约束会漂向某一端（模式坍塌/全个体化/全一刀切）

## 三步展开

### 第 1 步：unify——收进同一张图纸

找出两派方案的**共同模板**，把差异收敛为参数。

| 域 | A 派（粗/全局） | B 派（细/局部） | 统一模板 |
|---|---|---|---|
| 生成模型 | 单高斯 + W2 | 核密度 + KL | "分布模型 + 差异度量" |
| 推荐 | 全局模型（协同过滤，丢个体差异） | 全个体模型（过拟合，丢全局规律） | "共享参数 + 个体偏移"的参数化框架 |
| 风控 | 全规则（刚性，漏新型） | 纯模型（黑箱，漏可解释硬约束） | "规则层 + 模型层"的统一评分框架 |
| 评测 | 聚合指标（FID，盲区） | 逐条人评（贵，不可扩展） | "聚合 + 分层探针"的统一评测框架 |

**unify 失败的信号**：找不出共同模板 → 说明两派不同构，强行 unify 会丢掉其中一派的关键能力 → 回到"二选一 + 场景分流"，别硬套。

### 第 2 步：造中间粒度

在两端之间造**可调节**的档位（MGFlow：K 个高斯组件，1/4/16 并行）。

- 粒度参数必须**可调**（K 可设），不是造一个"折中版"了事
- 多档位**并行**跑对照（1/4/16 同时出分），让数据选档位，不是拍脑袋
- 判据：调大粒度 → A 派能力增强，B 派能力减弱，连续变化（而非跳变）= 真的造出了中间档位

### 第 3 步：加硬性约束锁分配

只有表达力（加组件/加参数）没有约束 = 模式坍塌迟早复发（分数失明：某类悄悄消失，梯度看不见）。

| 约束类型 | MGFlow 对应 | 其他域对应 |
|---|---|---|
| 配额锁定 | LP 质量约束：组件样本总质量 = 真实模式权重 | 推荐流类别配额、素材库占比、合成数据分布对齐 |
| 配对更新 | 生成侧第 k 组件只对齐真实侧第 k 个 | 个体模型只学自己那格的数据，不抢全局参数 |
| 固定参照 | 归一化用真实集固定差值，不随生成质量变 | 评测基线固定，不被当前输出自我开脱 |

**约束必须"硬"**：是分配上限/等式约束（优化问题的约束项），不是"正则化鼓励"——正则会被大梯度冲掉，约束不会。

## 与其他方法论的关系

- 与 multi-agent-coupling 的"三问体检"同构：都是先诊断结构（耦合度/粒度欠债），再决定拆不拆/怎么调，最后用硬判据复测
- 与 creation-density 的"闭环计分"互补：本方法论管"结构怎么改"，闭环计分管"改完怎么验收"
- 顺序纪律：unify 没做成 → 不许造粒度；粒度没调通 → 不许上约束（约束加在错误的粒度上会锁死错误的分配）
